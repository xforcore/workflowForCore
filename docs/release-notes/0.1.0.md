## workflowForCore 0.1.0

The first release: Microsoft's Windows Workflow Foundation 3 (.NET Framework 4.8 Reference Source) on .NET 10, on
Linux and Windows (issue #1, phase 1).

- **Packages:** `workflowForCore`, which brings `workflowForCore.ComponentModel`, `workflowForCore.Runtime` and
  `workflowForCore.Activities`: System.Workflow.ComponentModel, System.Workflow.Runtime and System.Workflow.Activities
  4.0.0.0, with Microsoft's public key token 31bf3856ad364e35, checked against .NET Framework 4.8's in CI.
- **Microsoft's code:** WF3's three folders of the .NET Framework 4.8 Reference Source, about 112,000 of their
  182,600 lines compiled; the designers, the debugger engine, WF4 interop and the ASP.NET parts aren't
  (docs/LIFT.md). The changes to Microsoft's files (docs/MODIFICATIONS.md) are on xforcore/referencesource's
  `workflowforcore` branch: designer types by name in attributes, no COM+ flow, no telemetry, performance counters
  on Windows only, webForCore's BinaryFormatter, no remoting.
- **Phase 1 features, tested on Linux and Windows and against .NET Framework 4.8:** `WorkflowRuntime` and
  `WorkflowInstance`, the default and manual schedulers, sequential and state-machine workflows defined in code, the
  base activities, `ExternalDataExchangeService`, `TransactionScopeActivity` and compensation, persistence
  (`Activity.Save`/`Load`, a host's own `WorkflowPersistenceService`, `SqlWorkflowPersistenceService`), tracking
  (`TrackingService`, `SqlTrackingService`) and rules (`.rules` resources, `RuleSet`, `PolicyActivity`).
- **workflowforcore-sql** (`workflowForCore.Sql`, a .NET tool) creates the persistence and tracking databases with
  .NET Framework 4.8's SQL scripts, which System.Workflow.Runtime carries.
- **Instance state** persisted by .NET Framework 4.8 resumes on workflowForCore, and the reverse: delegates in
  instance state are serialized in .NET Framework's format.
